`python3 tests/stands/action-first.py prepare` makes a fresh `/tmp/action-first.*` folder with a `.action-first-stand` marker and prints `catalog:`, `empty:`, `broken:`, `analysis:`, `empty-prompt:`, `broken-prompt:`, `steps-prompt:`, `form-prompt:`, `home:`, `session:` and `repo:` with their paths. - `repo.md`: the branch `global/AGENTS.md` whole, the line "for this task `~` is `<home>` and your current folder is `<session>`", then "fix the greeting typo in the zz greeter bot" (spaces, not hyphens: the lookup compares names with spaces, `-` and `_` taken as one).

`clean <folder>` removes only a folder that holds the marker `prepare` wrote and refuses any other with exit 1, removing nothing.

Every answer comes from a Claude Code subagent of the lead session (`general-purpose`, it writes files) on `agents.test-model` (`haiku`), never `claude -p`; the lead saves the answer text to the scratchpad. Each prompt bounds the subagent to the stand folders it names, and a run whose transcript reads a path under `tests/stands/action-first` or this change's folder is discarded (the grader and the references stay out of the measured agent's reach). The graded runs read the laid-out text (Needs); a run before that layout, with the branch text only inside the prompt, is a pre-check and proves nothing in Result.

Graders, all lines after `*`, backquotes, heading and quote markers are stripped and whitespace collapsed; a list item is detected on the raw line (`-`, `*` or `<n>.` at its start) before that; empty lines are not counted; a leading `Goal:` line and a leading `Check:` line (each also alone) are skipped unless the grade names them, and every line window counts from the line after them:

- `--grade-analysis <answer> <project>`: `actions first: yes|no` (within the first 5 non-empty lines stand one to three list items in a row, the whole run inside those lines, or a line starting with `No action follows:`), `effect named: yes|no` (every such item holds ` — ` and text after it), `file linked: yes|no` (one of the first 5 non-empty lines names a `.md` or `.csv` path (trailing punctuation stripped) that, resolved with links, lies inside `<project>`, exists and holds the action lines), `only analysis file: yes|no` (`git status --porcelain` of `<project>` lists only that file and there is no new commit, or it prints nothing and the only new commit adds only that file). A path outside `<project>`, absolute or through a link gives `file linked: no`.
- `--grade-goal <answer>`: `goal first: yes|no` (the first two non-empty lines start with `Goal:` and `Check:`, the next one is an action or `No action follows:`).
- `--grade-failure <answer>`: `failure named: yes|no` (one of the first 5 non-empty lines names `catalog.db` and a read failure: `error`, `cannot`, `could not`, `unable`, `fail`, `failed`, `failure`, `unreadable`, `corrupt`, `invalid` or `not a database` as words; no line starts with `No action follows:`).
- `--grade-form <answer>`: `form kept: yes|no` (the first non-empty line starts with `rows:`).
- `--grade-repo <home> <session> <reply>`: `edit in project: yes|no` (`bot.py` of `x/zz-greeter-bot` holds `"Hello from zz-greeter-bot"`), `other untouched: yes|no` (`zz-greeter-bot-old` has one commit and a clean status), `others named: yes|no` (the reply names `zz-greeter-bot-old`), `no copy in session: yes|no` (no file under `<session>` is named `bot.py` or holds `from zz-greeter-bot"` in its first 1 MB), `committed: yes|no` (a second commit, clean status), `project rules: yes|no` (its message starts with `greeter:`), `real Code untouched: yes|no` (the real `~/Code` has no `zz-greeter-bot` or `zz-greeter-bot-old` folder within 3 levels, as `prepare` checks), `no worktree left: yes|no` (`git worktree list` of `x/zz-greeter-bot` shows only the project itself).

An answer over 1 MB, an empty one, a truncated one (it ends inside an open code fence) or a non-UTF-8 one, a missing file or a wrong argument exits 1; unclosed inline `*` or backquotes are graded, not refused. The graders read `<session>` and the fixture repositories without following links, read at most 1 MB per file and 1,000 entries, and run git with `-c core.fsmonitor= -c core.hooksPath=/dev/null`.
