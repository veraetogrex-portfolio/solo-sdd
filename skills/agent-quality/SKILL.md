# agent-quality: качество агента доказывается сравнением

Агент — это промпт, модель, поиск, правила эскалации и данные вместе. «Стало лучше» засчитывается только тогда, когда новая версия обошла прежнюю на одном и том же наборе случаев и не ухудшила критичные.

## Порядок

1. **Версия.** Запиши, что сравниваем: модель, промпт (файл или коммит), настройки поиска, коллекции и дата данных, правила эскалации.
2. **Набор случаев.** Бери существующий: golden set — это размеченная таблица пользователя, её и используй. Нет набора — собери 20–50 реальных случаев из логов, включая критичные категории, и покажи пользователю до прогона.
3. **Что считается ответом.** Внутренняя заметка AI (AI note, черновик) — не ответ клиенту: её могли и не использовать. Ответом считается только отправленное сообщение. Смешивать их нельзя.
4. **Метрики** на одном наборе:
   - правильность ответа по разметке;
   - эскалации: обоснованные, лишние (не из разрешённых категорий), пропущенные;
   - опора на источник: ответ подтверждён найденными документами;
   - задержка и стоимость на случай.
5. **Базовая линия.** Сначала прогон текущей версии. Без неё изменение не оценивается.
6. **Стоимость до запуска.** Перед платным прогоном назови: число вызовов, модель, сумму, условие остановки. Предварительные проверки — на сохранённых ответах и самых дешёвых моделях.
7. **Изменение и повторный прогон** на том же наборе. Меняй одну вещь за раз, иначе не понять, что сработало.
8. **Живая проверка.** Отдельно посмотри 5–10 реальных диалогов после изменения: набор случаев не покрывает всё.

## Данные

- Новые правила оценки применяются к новым записям. Пересчёт исторических данных — только по прямой просьбе и после описания, что изменится в накопленной базе.
- Перед выводом сверь схему, период, единицы и что именно означает число.

## Отчёт (по-русски)

```
Сравнивали: <версия A> → <версия B>, набор <имя, N случаев>
Правильность: <A> → <B>
Эскалации лишние / пропущенные: <A> → <B>
Опора на источник: <A> → <B>
Задержка, стоимость на случай: <A> → <B>
Ухудшилось: <случаи и категории> | ничего
Вызовов и сумма: план <…>, факт <…>
Вывод: принять B | оставить A | нужно ещё <что>
```

## Ошибки

| Мысль | Что делать |
|---|---|
| «Ответы стали лучше, я посмотрел» | Нужна таблица A против B на одном наборе |
| «Прогоню 500 случаев на сильной модели» | Сначала оценка суммы и согласие |
| «AI note совпала с разметкой — агент ответил верно» | Считать только отправленные ответы |
| «Поменяю промпт, модель и поиск сразу» | Одно изменение за прогон |
| «Пересчитаю старые звонки по новым правилам» | Только новые, если не просили иначе |
| «Логов много, значит, метрики есть» | Метрика — это число на размеченном наборе |
