# ui-check: сверка интерфейса с макетом в браузере

Интерфейс сдаётся по снимкам экрана и кликам, а не по коду. Нет снимка — нет «готово».

## Порядок

1. **Эталон.** Найди макеты в проекте (`design/`, `макеты`, экспорт Figma, уже готовые страницы в новом дизайне). Макетов нет — эталоном служат готовые соседние экраны.
2. **Сборка.** Открой то, что реально загружает пользователь: собранный артефакт, запущенный сервер, стенд. Запускай по README; если по нему не запускается, почини README. Перезапусти сервер, если менял код.
3. **Снимки.** Интерфейс продукта: ширина 1280 и 390, светлая и тёмная тема, если их две. Личный HTML-отчёт без запроса внешней публикации: достаточно отображения и кликов на десктопе; адаптивная проверка не требуется.
4. **Сверка с эталоном по списку:** сетка и отступы, шрифты и размеры, цвета, состояния элементов, тексты, порядок блоков, отсутствие горизонтальной прокрутки; поведение при узкой ширине — когда шаг 3 требует адаптивной проверки.
5. **Клики.** Нажми каждый изменённый или соседний элемент управления: кнопки, списки, поля, вкладки. Запиши, что произошло после нажатия.
6. **Правка** расхождений, затем повтор шагов 3–5 один раз.

## Условия

- Браузер или стенд недоступен: напиши «интерфейс не проверен» и причину. Не заменяй проверку чтением кода.
- Правка затронула общий стиль или скрипт: проверь и соседние экраны, которые его используют.
- В задаче названы конкретные страницы: меняй только их.

## Отчёт

```
Проверено: <экраны, ширины>
Снимки: <пути к файлам>
Расхождения с макетом: <список> | нет
Клики: <элемент — результат>; не работает: <список> | всё работает
Не проверено: <что и почему> | ничего
```
