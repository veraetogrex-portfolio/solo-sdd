# project-init: проект, готовый к /spec-next

Готово, когда в папке можно сразу сказать `/spec-next` обоим агентам и они получат одни и те же правила без напоминаний.

## Порядок

1. **Режим.** Определи по задаче: `demo` (показ, защита, прототип) или `prod`. Режим не указан и задача не про показ — выбери `prod` и запиши решение.
2. **Git.** `git init`, если нет. Дан адрес — добавь remote. `.gitignore`: `.env`, ключи, сертификаты, рабочие данные. `openspec/`, `AGENTS.md` и `CLAUDE.md` в `.gitignore` не вноси. Существующий `.gitignore` не меняй; если он не скрывает `.env`, скажи об этом в отчёте.
3. **OpenSpec.** `openspec init --tools claude,codex`. Если проект уже инициализирован — `openspec update`. В существующем `openspec/config.yaml` сохраняй прежний контекст и настройки, добавляй только недостающее. Для нового конфига:
   ```yaml
   schema: solo
   context: |
     Language: ru. Structural headings and SHALL/MUST stay in English.
     Режим: demo | prod
     Замысел: <2–3 предложения — что это и для кого; с ним сверяется каждый новый change>
   operations:
     apply:
       guidance:
         - Тесты и приёмка на самых дешёвых моделях
   ```
   Схемы `solo` нет (`openspec schemas`) — оставь `spec-driven`.
   Шаблоны конфига, проектных проверок `openspec/analyze.md` и `docs/waiting.md` — в `~/Code/tools/sdd/solo-sdd/templates/`. Порядок работы целиком — `~/Code/tools/sdd/solo-sdd/ALGORITHM.md`.
4. **`.env.example`** с пустыми полями и комментарием, где взять значение. Существующие `.env` и `.env.example` сохраняй; добавляй только отсутствующие поля с пустыми значениями. Если `.env` отсутствует, создай его с пустыми полями. Значения секретов в чат не проси: назови поле, которое нужно заполнить.
5. **`AGENTS.md`** по разделам ниже. Существующий `AGENTS.md` сохраняй и дополняй только недостающими правилами; не заменяй его строкой импорта. Факты бери из кода и `package.json` / `pyproject.toml`, не выдумывай команды.
5a. **`DESIGN.md`.** Только в проекте с интерфейсом: вне `node_modules/`, `tests/`, `openspec/` и скрытых папок есть файл `.html .htm .css .scss .sass .less .tsx .jsx .vue .svelte` (это `UI_EXT` хука `global/work_hooks.py`) или владелец в запросе прямо назвал интерфейс (сайт, лендинг, приложение с экранами). Иначе `DESIGN.md` не создаётся и раздела «Интерфейс» в `AGENTS.md` нет. Создай по шаблону `~/Code/tools/sdd/solo-sdd/templates/DESIGN.md`. Переноси только слова владельца из запроса или чата: каждое слово в то поле, о котором оно сказано; ничего не домысливай, не копируй в соседние поля и не дописывай пометок от себя. Слова о стиле в целом («стиль: спокойный», «строгий») идут в «Характер», в «Настроение» — только то, что владелец назвал настроением. Поле, куда попал хотя бы один ответ владельца, считается заполненным, даже если ответ неполный. Дайлы из слов не выводятся: строка `Dial` остаётся с `n`, пока владелец не назвал числа; строка `Dial` с `n` считается пустым полем. Есть пустые поля — одна строка в таблице `docs/waiting.md` (нет файла — создай по `~/Code/tools/sdd/solo-sdd/templates/docs/waiting.md`): Change `—`, Пункты `—`, Чего ждём «DESIGN.md: заполнить поля <список пустых полей>», От кого — владелец, С какого числа — дата. Файла `WAITING` нет. Пустых полей нет — строки нет. Повторный запуск: существующий `DESIGN.md` сохраняй, заполненные поля не меняй, недостающие добавляй пустыми, пустые заполняй только ответами владельца из этого запроса; строку в `docs/waiting.md` обновляй, а не дублируй, если пустых полей не осталось — удали.
6. **`CLAUDE.md`**: если файла нет — создай с одной строкой `@AGENTS.md`, чтобы Claude читал те же правила сам. Если файл есть — добавь `@AGENTS.md`, когда ссылки ещё нет; прежние инструкции сохраняй.
7. **Проверка.** `openspec validate --all --strict --no-interactive`, команды из таблицы AGENTS.md действительно запускаются.
7a. **Коммит артефактов.** `git check-ignore -v -- openspec/ AGENTS.md CLAUDE.md`, затем по случаю:
   - `.gitignore` создан этим запуском: `git add -- .gitignore AGENTS.md CLAUDE.md openspec && git commit -m "project-init: правила и спеки" -- .gitignore AGENTS.md CLAUDE.md openspec`;
   - `.gitignore` уже был, вывод пуст: те же две команды без `.gitignore` в путях (все три уже в коммите без изменений — шаг пропускается);
   - `.gitignore` уже был, вывод не пуст: `.gitignore` не меняй и артефакты не коммить. В отчёт: путь, строка `.gitignore`, которая его скрывает, и цена — такие артефакты переносятся в worktree только через `sdd-worktree.py`; в публичном репозитории спеки с цитатами владельца стали бы видны всем, поэтому решение за ним.
   В коммит идут только названные пути: чужие правки остаются незакоммиченными.
8. **README.** Проект запускается с нуля по README, без знаний из чата: установка, `.env` из `.env.example`, команда запуска, как понять, что заработало. Пройди эти шаги сам в чистой оболочке. Не запустилось — чини README или проект, это часть задачи.

## Разделы AGENTS.md

| Раздел | Содержимое |
|---|---|
| Назначение и режим | Одна-две фразы о проекте. `Режим: demo` или `prod` |
| Источники истины | Что считать контрактом, что историческим контекстом |
| Работа по спекам | Четыре правила ниже, дословно |
| Команды | Таблица: установка, сборка, тесты, запуск, живой прогон. Команда тестов — по правилу ниже |
| Карта проекта | Папки и их роль |
| Границы и инварианты | Что нельзя ломать |
| Проверка | Что запускать перед «готово» |
| Безопасность | Секреты, платные запросы, прод |
| Интерфейс (только в проекте с интерфейсом) | Ссылка на `DESIGN.md`: направление интерфейса, заполняет владелец |
| Поставка | Для `spec-dispatch` и `ship`: пункт «Режим:» — `local` (merge в локальную основную ветку, затем `ship`) или `pr` (каждый change — свой PR), «Merge:» — `squash`, `merge` или `rebase`, «Заголовок PR:» — правило, «Деплой:» — запускает ли merge в основную ветку выкатку и куда |
| Рабочая копия (необязательный) | Для `spec-dispatch`, если часть артефактов игнорируется git: пункт «Пути:» — что ещё скопировать в worktree, пункт «Подготовка:» — команда для него (установка зависимостей), пункт «Оркестраторов:» — число одновременных оркестраторов `spec-dispatch` (по умолчанию 2), пункт «Общие:» — пути в обратных кавычках, которые change правят часто и которые не мешают параллельной работе; путь с `/` на конце делает общими все файлы под каталогом: `docs/` для документов, каталог стендов живой проверки |

Команда тестов при разделе «Рабочая копия»: посчитай `max(1, ⌊ядра / N⌋)`, где ядра — вывод `sysctl -n hw.ncpu` (Linux — `nproc`), N — пункт «Оркестраторов:» (по умолчанию 2), и запиши в таблицу готовую команду с этим числом, без формулы и условий: vitest и jest — `--maxWorkers=<число>` (через npm: `npm test -- --maxWorkers=<число>`), pytest с установленным pytest-xdist — `-n <число>`. Раздела нет или исполнитель тестов не умеет ограничивать потоки — команда без флага. В существующей команде без флага добавь его, уже стоящий флаг не пересчитывай.

Правила для раздела «Работа по спекам»:

- За один заход один change, до архива.
- Без уточняющих вопросов: обоснованное решение, запись в отчёт.
- Работа вне текущей спеки оформляется новым change.
- После закрытия `tasks.md` — самостоятельный живой тест до отчёта о готовности.

## Режим demo

Без докера и деплоя. Данные выдуманные или эмуляция, кроме цифр, отзывов и клиентов владельца: они остаются заглушками `[нужны данные: <что>]`. Один воспроизводимый скрипт показа: сид данных → сценарий → вывод. В README первая строка — команда запуска.
