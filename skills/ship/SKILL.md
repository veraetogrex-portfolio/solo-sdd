# ship: от рабочего дерева до смёрдженного main

Готово, когда локальная основная ветка совпадает с удалённой и в рабочем дереве нет ни одного необъяснённого файла. Открытый PR без мёрджа — это «не готово». Исключение: push или merge выкатывает на прод, а согласия на деплой нет.

## Порядок

1. **Правила репозитория.** Прочитай `AGENTS.md`, `CLAUDE.md`, `CONTRIBUTING`, правила веток. Они определяют, пушить напрямую или через PR, и формат сообщений.
2. **Деплой.** Найди, что запускается на push или merge любой затронутой ветки: `.github/workflows`, `.gitlab-ci.yml`, git-хуки, автодеплой хостинга, правила проекта. Если это выкатка на прод — перед этим push или merge остановись и спроси: что выкатится, на какой сервер, что будет с данными. Сначала подготовь проверенные изменения и коммит для review; согласие требуется перед действием, запускающим деплой. До согласия PR остаётся открытым, если его создание не запускает деплой.
3. **Опись.** `git status` и `git diff --stat`. Каждый изменённый файл получает одно из двух: попадает в коммит или назван в отчёте с причиной, почему оставлен.
4. **Секреты.** В коммит не идут `.env`, ключи, сертификаты, локальные настройки агента, исключённые из git. Нашёл секрет в диффе — остановись и скажи.
5. **Коммиты.** Группируй по смыслу, сообщение в стиле истории репозитория.
6. **Пуш.** Без `--force`. Отклонён — `git pull --rebase`, разреши конфликты, повтори.
7. **PR.** Если нужен: `gh pr create`, дождись проверок, смёрджи сам (`gh pr merge`). Авто-мёрдж не включай.
8. **Синхронизация.** Переключись на основную ветку, `git pull`.
9. **Проверка.** `git fetch && git status` чистый, `git rev-parse HEAD` равен `git rev-parse origin/<основная>`.

## Если не получилось

| Ситуация | Действие |
|---|---|
| Мёрдж или пуш заблокирован правами агента | Назови точную строку разрешения, которую нужно добавить, и повтори после |
| Проверки PR упали | Чини и пушь в ту же ветку |
| В дереве чужие изменения | Не откатывай. Коммить свои, чужие перечисли в отчёте |
| Нет удалённого репозитория | Проверь конфиг и историю проекта. Адрес не найден — зафиксируй блокер, не создавай внешний репозиторий без просьбы |
| Push или merge запускает деплой на прод | Остановись перед этим действием, спроси. Подготовленные изменения и ссылку на PR, если он открыт, дай в отчёте |
