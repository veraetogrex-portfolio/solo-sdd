# blockers: блокеры и находки — в отдельные change, работа продолжается

Аргумент (необязательный): что именно вынести. Без аргумента собери всё сам: блокеры и находки за границами текущей работы из этой сессии, раздел «Not Verified» в `verification.md` текущего change, пункты «найдено вне change» из отчётов.

## Порядок

1. **Список.** Для каждого пункта: что блокирует или что найдено, чего ждём (доступ, решение владельца, данные, внешний сервис), кто может снять.
2. **Разделение.**
   - Блокер — работа есть, но ждёт внешнего условия.
   - Находка — работа за границами текущей спецификации.
3. **Проект с OpenSpec.** Номер и имя бери по образцу соседних change (`openspec list --json`, следующий свободный номер).
   - Блокеры текущего change — один новый change `<номер>-<тема>-blockers`: `proposal.md` (что ждём и зачем), `tasks.md` (шаги после снятия условия), файл `WAITING` с условием, строка в `docs/waiting.md`. В `verification.md` текущего change — ссылка на него.
   - Находки — по одному change на независимую тему: `proposal.md` и `tasks.md`, без `WAITING`.
   - Каждый новый: `openspec validate <id> --strict --no-interactive`.
4. **Проект без OpenSpec.** Блокеры — в `docs/waiting.md`, находки — в `docs/backlog.md`. Нет файла — создай.
5. **Коммит.** Новые артефакты — отдельным коммитом по правилам проекта (`/ship`).
6. **Продолжение.** Текущий change меняй только ссылками. Если ты его вёл — продолжай со следующего пункта `tasks.md`, не останавливаясь.
