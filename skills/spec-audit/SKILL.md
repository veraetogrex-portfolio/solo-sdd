# spec-audit: независимая сверка кода со спекой

Ревью делает агент, который этот код не писал и не видел рассуждений автора. Находки — гипотезы, пока не проверены по коду. По умолчанию файлы не меняй; отчёт — в чате.

## Порядок

1. **Объём.** Названный change или спека; иначе все активные change и `openspec/specs/`.
2. **Базовая линия.** Запусти проверки проекта из `AGENTS.md` и запиши, что падало до ревью.
3. **Независимый ревьюер** в режиме только чтения, с чистым контекстом: сначала собственный субагент без истории автора (в Codex: `fork_turns="none"`). CLI — только если собственного инструмента субагентов нет и вызов разрешён по правилам платных запросов; выбери доступный CLI с режимом чтения, например `codex exec --color never --sandbox read-only -C <repo> - < задание` или `claude -p --permission-mode plan < задание`. Нет разрешённого инструмента — отметь независимое ревью как непроведённое.
   
   Задание: пути к спеке и коду, просьба пройти по каждому требованию и по коду, файлы не менять. Большой объём дели: одна спека — один ревьюер.
4. **Таблица требований.** Каждое требование спеки получает строку: `выполнено | частично | нет` и `файл:строка`.
5. **Проверка находок.** Каждую находку подтверди по коду или запуском. Неподтверждённые убери.
6. **Сквозной путь.** Хотя бы один сценарий проверь до того места, которое видит пользователь: собранный артефакт, экран, ответ сервиса. Модульные тесты этого не заменяют.
7. **Отчёт.** По умолчанию в чате. `bugs.md` в папке change (нет change — в корень) записывай только если пользователь попросил файл или действующие правила проекта требуют этот файл. У каждой находки: сценарий сбоя (что делает пользователь → что получает), место `файл:строка`, доказательство (вывод команды, запрос, снимок), приоритет. Приоритет ставь по влиянию на пользовательский путь: P0 ломает сценарий, P1 расходится со спекой, P2 риск, P3 чистота.
8. **Исправление.** P0 и P1 чини только если исправление явно разрешено в текущей задаче, затем повтори проверки. Просьба проанализировать, провести ревью или аудит сама по себе не разрешает правки. Пользователь сказал «ничего не меняй» или «только ревью» — остановись на шаге 7.

## Отчёт

```
Требований: <всего> — выполнено <n>, частично <n>, нет <n>
P0: <n>  P1: <n>  P2: <n>  P3: <n>
Главное: <до трёх находок: сценарий — эффект для пользователя>
Исправлено: <список> | только ревью
Сквозной сценарий: <что проверено, результат>
Файл: <путь к bugs.md> | не создавался — отчёт в чате
```

## Ошибки

| Ошибка | Исправление |
|---|---|
| Ревью собственным контекстом | Запусти второго агента |
| Ревьюер правит файлы | Только режим чтения |
| Находка принята на веру | Проверь по коду перед правкой |
| «Тесты зелёные» как вывод | Нужен сквозной сценарий |
