# What goes where

How `solo-sdd install` and `sync.py push` lay the repository out in the agent folders. The commands are in [README.md](../README.md).

The deployment map is `targets.json`. There are 20 skills: 15 of the algorithm and 5 manual commands (`relay`, `blockers`, `report`, `health`, `changes`).

| What | Where |
|---|---|
| `skills/<name>/SKILL.md`: `spec-plan`, `spec-analyze`, `spec-next`, `spec-audit`, `project-init`, `context-resume`, `work-status`, `ship`, `ui-check`, `copy-check`, `debug-profile`, `evidence-research`, `agent-quality`, `relay`, `blockers`, `report`, `health`, `changes` | `~/.agents/skills`, `~/.codex/skills`, `~/.claude/skills` |
| `integrations/antislop/` (the bundled integration `antislop`, a pinned copy of the anti-slop rules: the core `core.md`, `ui.md`, `human.md`, `layoutmobile.md`, `contrast-check.py`, `references/`, `copywriting.md`; the copy's licenses, README, VERSION and `integration` description are not deployed; updated only by replacing the copy) | `<root>/ui-check/antislop/` (everything except `copywriting.md`) and `<root>/copy-check/antislop/` (`core.md`, `copywriting.md`) in `~/.agents/skills`, `~/.codex/skills`, `~/.claude/skills` |
| `integrations/security-audit/` (the bundled integration `security-audit`, a pinned copy of `cloudflare/security-audit-skill`: `METHOD.md` from its `SKILL.md`, the attack class references, `report-schema.json`, the validators; its license, README, VERSION and `integration` description are not deployed; updated only by replacing the copy) | `<root>/spec-audit/security/` in `~/.agents/skills`, `~/.codex/skills`, `~/.claude/skills` |
| `skills/codex-orchestration/SKILL.md` | `~/.agents/skills`, `~/.claude/skills` |
| `skills/spec-dispatch/SKILL.md` (hands changes to Opus orchestrators, Claude Code only) | `~/.claude/skills` |
| `global/AGENTS.md` (the solo-sdd rules, as a block) | the project `AGENTS.md` by `solo-sdd init`; with `install --global-rules`, `~/AGENTS.md`, `~/.codex/AGENTS.md`, `~/.claude/CLAUDE.md` |
| `ALGORITHM.md` | `~/.local/share/solo-sdd/ALGORITHM.md` |
| `templates/` (`solo-sdd/project.md`, `solo-sdd/analyze.md` for `solo-sdd init`, `docs/waiting.md`, `DESIGN.md`, `solo-sdd/change/` for `solo-sdd new`) | `~/.local/share/solo-sdd/templates/` |
| `pyproject.toml`, `solo_sdd/` (the `solo-sdd` command; deployment logic in `solo_sdd/layout.py`, `sync.py` is a wrapper) | not deployed, installed as a package |
| `global/process-guard.py` (hook that forbids stopping processes directly) | `~/.claude/hooks/process-guard.py` |
| `global/work_hooks.py`, `global/model-policy.json` (workflow hooks and the model policy) | `~/.claude/hooks/` |
| `global/sdd_worktree.py` (worktree preparation for `spec-dispatch`: `setup` copies the git-ignored `openspec/`, `AGENTS.md`, the paths of the "Working copy" section and individually ignored project documents, links `node_modules` and `.venv`; `transport` carries them back by a three-way merge, `undo` reverts the transfer, `remove` removes the worktree, `discard` removes a worktree without own commits together with its branch after a failed preparation) | `~/.local/bin/sdd-worktree.py` |
| `global/sdd_dispatch_plan.py` (queue for `spec-dispatch`: counts ready open changes (no `CLAIM`, `WAITING`, branch `change/<id>`, the change folder is committed, dependencies archived), the order by the critical path and hard conflicts by requirements and `Impact` files, except shared paths; prints whom to launch, who waits and which pairs go together on a shared path; prints which of `openspec/`, `AGENTS.md`, `CLAUDE.md` are ignored by git) | `~/.local/bin/sdd-dispatch-plan.py` |
| `global/sdd_pr.py` (PRs for `spec-dispatch`: `open` pushes the worktree branch and opens a PR (or takes an open one), `wait` waits for CI and answers `green`, `red` or `infra` with the log tail; `green` only when all required checks from the branch rules passed, a required check that did not start within 300 s after the others gives `infra` with its name; after green checks, open code scanning alerts on the PR give `codeql` (code 8) with their lines; `merge` merges the PR by a REST API request with the hash of the checked commit after checking the checks); `ship` in one command updates the branch, runs `refresh`, push, opens the PR and waits for CI (codes 0, 3, 4, 6, 8, 1), `land` merges with the head hash, pulls the main folder, carries the artifacts and removes the worktree and branch, stopping at the first failure (codes 0, 1, 5, 7; a repeated `land` continues without a second merge); before merge `merge` and `land` check the PR files against the "Owner only:" item of the "Delivery" section of the main folder's `AGENTS.md` and `.github/workflows/**`: a match gives code 8 "waits for the owner", the PR stays open | `~/.local/bin/sdd-pr.py` |
| `global/sdd_dispatch.py` (`spec-dispatch` mechanics: `accept` parses the status block, runs the `VALIDATE` and `LIVE` commands in the worktree and checks codes and output, does not run `TESTS`; `land-local` in `local` mode checks that the main folder is clean, merges with `--no-ff`, transfers, checks, rolls back with a rerun of the failed check on main, and cleans up; a branch that touches "Owner only:" paths is stopped with code 8 before merge) | `~/.local/bin/sdd-dispatch.py` |
| `global/sdd_eval.py` (replaying archived changes on project copies and comparing dispatcher configurations: `setup` prepares copies, `run` runs `spec-dispatch`, `metrics` counts time and cost, `compare` runs the oracle tests and prints a report; details in `tests/eval/README.md`) | `~/.local/bin/sdd-eval.py` |

`global/work_hooks_settings.py` is run by hand: it connects the hooks in `~/.claude/settings.json` and sets the subagent depth to 2 (`env.CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`; a value you set is left alone), and in `autoMode.allow` it keeps one rule about merging own PRs (`sdd-pr.py merge`, `land`, and `gh pr merge` from `/ship` only in a repository without `solo-sdd/`; not under `delivery.merge-by: human`) and updating the change branch: a repeated run replaces it by the prefix `The owner's merge rule (solo-sdd)` or the older `The owner's global rules (~/.claude/CLAUDE.md, section 13)`. `sync.py` does not touch the settings.

New project templates are deployed into `~/.local/share/solo-sdd/templates/`; `solo-sdd init` takes them from the package. Not deployed, kept in the repository: `tests/` (`tests/stands/` holds live scenario stands), `scripts/publish-first.sh` (first publication, one-off), `scripts/release_check.py` (release check), `.github/workflows/test.yml` (CI), `.github/workflows/release.yml` (registry release, see `docs/release.md`). `AGENTS.md` and `CLAUDE.md` at the root are internal work on solo-sdd itself; `solo-sdd/` (specs and open changes of solo-sdd itself) is kept in the repository; its change archive `solo-sdd/changes/archive/`, `docs/waiting.md` and `docs/rules-audit.md` live only in the author's working folder.
